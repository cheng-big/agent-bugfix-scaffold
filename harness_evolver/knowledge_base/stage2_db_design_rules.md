# Stage 2 — 数据库与模型设计防御规范

## Baseline

- [ ] 每张业务表具备主键、创建/更新审计字段、软删除字段和必要的业务唯一键。
- [ ] 唯一约束与状态机一致；“同点同月”等约束考虑软删除、驳回重提和并发写入。
- [ ] 外键、删除策略和历史快照明确，禁止当前主档变更反向污染已提交快照。
- [ ] 为数据范围、时间范围、状态筛选、关联查询和幂等键设计复合索引，并说明最左前缀。
- [ ] 字段长度来自真实样本和上限；金额、面积、计量使用 Decimal，禁止浮点误差。
- [ ] `BIGINT` 等跨语言 ID 在 JSON 契约中以字符串传输，并用超过 `2^53-1` 的值回读验证。
- [ ] 版本化实体使用 `(business_key, version)` 唯一键，当前版本与历史版本更新在同一事务。
- [ ] 并发敏感写入明确乐观锁/悲观锁、重试、幂等和唯一冲突转换策略。
- [ ] Flyway 等迁移只增不改；上线前验证空库、存量库、回滚/补偿和执行耗时。
- [ ] 种子数据、测试数据与生产数据分离，测试账号和默认密码有删除门禁。
