# Stage 4 — 测试用例生成盲区补偿矩阵

## Baseline

| 维度 | 强制用例 |
|---|---|
| 参数边界 | null、空串、最小/最大值、超长、非法枚举、精度、`BIGINT > 2^53-1` |
| 状态机 | 每条合法迁移、每条非法迁移、重复提交、驳回重提、锁定后写入、不可逆动作 |
| 角色权限 | 每角色正向动作、跨区县/跨租户读取、跨范围写入、只读角色接口级拒绝 |
| 数据上下文 | 至少两条真实父级数据，切换后列表/表单/缓存/请求参数全部改变且不串数据 |
| 数据库 | 唯一冲突、并发写、索引命中、外键失败、迁移空库/存量库、快照不被反改 |
| API 契约 | 200/400/401/403/500、中文错误、ID 类型、分页边界、导入部分失败 |
| 浏览器 UI | loading/empty/error/retry、长文本、窄屏、键盘焦点、导航遮挡、无嵌套导航 |
| 第三方 SDK | Key 缺失、网络失败、首次失败后重试、域名限制、容器 resize、降级状态 |
| 多端构建 | H5/PC/小程序分别 build；secret 与平台 SDK 只存在于目标产物 |
| 真实运行态 | 构建产物哈希/JAR 时间、Flyway 版本、健康检查、接口回读、浏览器可见结果 |
| 设备证据 | 真机/模拟器 AppID、地图/定位、软键盘、安全区、picker、上传权限 |

### 生成规则

- Mock 只验证局部逻辑；关键链路必须使用真实 API、数据库回读和可见 UI 证据。
- “接口 200”“编译通过”“覆盖率高”都不能单独判定完成。
- 每个历史 Bug 至少生成一个失败前置条件、一个防回归断言和一个证据路径。
- 测试失败必须区分产品缺陷、环境阻塞、历史基线和无关模块，不用修改无关代码换绿。
