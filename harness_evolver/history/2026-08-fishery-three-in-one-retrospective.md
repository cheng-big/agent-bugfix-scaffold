# 项目复盘待办

> 用途：统一记录项目实施期间的用户反馈、根因、处置结果与脚手架改进候选。
> 复盘时点：项目结束后统一处理；当前不因本文直接修改脚手架。
> 最后更新：2026-08-28

## 一、记录规则

- 用户明确指出的问题记为 `U-*`，优先保留用户的业务意图。
- 实施、测试或交付过程中暴露的工程问题记为 `E-*`。
- 由上述问题推导的脚手架改进候选记为 `S-*`；只是候选，复盘时再决定是否实施。
- 状态仅使用：`待处理` / `已修复待复盘` / `已验证待复盘` / `复盘已关闭`。

## 五、项目结束时的复盘清单

1. 逐项回看 `U-*`：修复是否只治了当前页，还是已变成系统级规则。
2. 逐项评审 `S-*`：判定“接受 / 拒绝 / 延后”，记录理由、负责人和目标版本。
3. 对 P0 候选做投入产出评估：需要多少脚本/契约改造，能阻断多少返工。
4. 检查 03 页面契约、05 逐系统建造、06 做实验证三个阶段的责任边界是否重叠或留白。
5. 将接受的改进落到 `.agent/process.json`、schema、命令实现和脚手架自测，不只修文档。
